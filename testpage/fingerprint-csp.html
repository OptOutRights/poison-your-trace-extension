Poison your Trace, strict-CSP fingerprint test page

Open this page through the CSP header server — npm run testpage:csp, then http://127.0.0.1:8778/fingerprint-csp.html — so it is served with a strict script-src 'self' Content Security Policy header, the kind banks and big-tech sites use. The page verifies live that inline <script> injection is blocked here, then reads every fingerprint signal and marks each green (✓ uniformized) or red (✗ real device leaking). Because the overrides now run as a world: "MAIN" content script the browser injects, they apply even under this CSP: with the extension enabled every row should be green. Under the old inline-<script> injection they would be red, because the page CSP blocked it. The verdict at the top states the result plainly.
